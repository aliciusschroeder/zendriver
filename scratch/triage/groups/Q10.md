# Group Q10 (tab-call-args)

queue: fix  |  triage severity: wrong-result  |  triage fix kind: local

## Claim
Tab.__call__ passes text and selector to wait_for positionally in swapped order, so tab(text=...) runs a CSS query and tab(selector=...) runs a text search

## Files
zendriver/core/tab.py (Tab.__call__)

## Triage fix strategy (a hypothesis, not a requirement)
Pass by keyword: self.wait_for(selector=selector, text=text, timeout=timeout).

## Triage test approach
Browser-free: patch the tab instance's wait_for and assert the arguments; optionally a real-browser check that tab(text=...) finds text.

### A7.1: Tab.__call__ passes text and selector to wait_for in swapped positions, so tab(text=...) never finds anything
- where (may drift): zendriver/core/tab.py:Tab.__call__:1966
- finder severity: wrong-result
- claim: __call__(self, text=None, selector=None, timeout=10) calls `self.wait_for(text, selector, timeout)` by position, but the signature is wait_for(selector, text, timeout). So `await tab(text="please press")` or `await tab("Login")` runs query_selector("please press") as a CSS selector. It matches nothing, polls for the whole timeout and raises TimeoutError, even though the text is on the page. `tab(selector=...)` only works by luck: the selector goes to find_element_by_text, whose DOM.performSearch also accepts CSS.
- finder evidence (unverified): Probe (real headless Chromium): `{'text': 'please press'} raised TimeoutError time ran out while waiting after 3.0s`, while `wait_for(text='please press') -> <p id="p">please press the button below</p>`. With probe1, `tab(text='Sign in now')` also raised TimeoutError while wait_for(text=...) found the button.
- finder repro idea: Load a page with <p>please press the button below</p>. `await tab(text='please press', timeout=3)` raises TimeoutError after 3s. `await tab.wait_for(text='please press')` returns the <p>.

### A6.8: Tab.__call__ passes text and selector to wait_for in swapped positions, so tab(text=...) runs a CSS query and tab(selector=...) runs a text search
- where (may drift): zendriver/core/tab.py:Tab.__call__ (caller of Tab.wait_for):1966
- finder severity: wrong-result
- claim: __call__(text, selector, timeout) calls `self.wait_for(text, selector, timeout)`, but the signature is wait_for(selector, text, timeout). So await tab(text='Hello needle') calls wait_for(selector='Hello needle'), and query_selector('Hello needle') never matches. It loops for the whole timeout and raises TimeoutError even though the text is on the page. await tab(selector='#p1') becomes a text search for '#p1'; it only happens to work because DOM.performSearch also tries the query as a CSS selector. Note: __call__ is just past my scope's end; I report it because it is the public entry point into wait_for.
- finder evidence (unverified): probe1.py: "[tab(text='Hello needle')] EXC in 2.02s -> TimeoutError: time ran out while waiting" vs "[wait_for(text='Hello needle')] OK in 0.00s -> <p id="p1">Hello needle world</p>".
- finder repro idea: Page <p id='p1'>Hello needle world</p>: await tab(text='Hello needle', timeout=2) raises TimeoutError, while await tab.wait_for(text='Hello needle', timeout=2) returns the <p>. Fix: self.wait_for(selector=selector, text=text, timeout=timeout).

### A12.1: Tab.__call__ passes text and selector to wait_for in swapped order, so tab(text=...) never searches by text
- where (may drift): zendriver/core/tab.py:Tab.__call__:1966
- finder severity: crash
- claim: await tab(text="Apples") (or positional await tab("Apples")) on groceries.html. __call__(text, selector, timeout) calls self.wait_for(text, selector, timeout), but the signature is wait_for(selector, text, timeout). So the text is used as a CSS selector: query_selector("Apples") polls until the timeout, then `if text:` is None and it raises TimeoutError('time ran out while waiting'). Text that is not a valid selector (e.g. "Sign up!") makes query_selector raise ProtocolException at once. tab(selector="li") only works by luck, because find_element_by_text uses DOM.performSearch, which also accepts selectors.
- finder evidence (unverified): Probe against real headless Chromium (detect-A12/probe1.py) printed: `call(text=Apples) raised TimeoutError time ran out while waiting`; `wait_for(text=Apples) -> script` (it finds the text); `call(selector=li) -> li 'Apples'` (works only by accident). git log -S shows the swapped call has been there since dd9a4f8 or earlier.
- finder repro idea: tab = await browser.get(sample_file('groceries.html')); await tab(text='Apples', timeout=1) raises TimeoutError, while await tab.wait_for(text='Apples', timeout=1) returns an element.
