### A9.5: cdp_get_module cannot map multi-word CDP domains, so manual X.enable(params) goes untracked and zendriver re-sends X.enable() with default params (the bug class PR #253 fixed, still live for WebAuthn, FedCm and others)
- where (may drift): zendriver/core/util.py:cdp_get_module:300
- finder severity: wrong-result
- claim: await tab.send(cdp.web_authn.enable(enable_ui=True)) (or cdp.fed_cm.enable(disable_rejection_delay=True)). Then tab.add_handler(cdp.web_authn.CredentialAdded, h), then any tab.send(...). Connection.send -> _update_manual_domain('WebAuthn') -> cdp_get_module('webauthn'): getattr(cdp, 'webauthn') fails, importlib.import_module('webauthn') raises ModuleNotFoundError, and that is caught with a debug log and return. The domain is never added to manually_enabled_domains. On the next send, _register_handlers sees a handler for an untracked domain and sends domain_mod.enable() with no arguments, which resets the caller's enableUI / disableRejectionDelay to the default. Single-word domains like Network and Fetch map correctly, which is why PR #253's fix (manual tracking) works for them. Affected domains: DOMStorage, DOMSnapshot, IndexedDB, LayerTree, HeapProfiler, ServiceWorker, WebAudio, WebAuthn, FedCm, DeviceAccess, HeadlessExperimental, PerformanceTimeline, BluetoothEmulation, SmartCardEmulation, WebMCP. The manual-disable bookkeeping (removal from enabled_domains) is skipped for these too. A bare import_module of the lowercased name can also import an unrelated top-level module of that name.
- finder evidence (unverified): Probe output: 'manually_enabled_domains: [\'network\']' (web_authn missing after WebAuthn.enable). With the handler added: 'methods sent for that one call: [\'WebAuthn.enable\', \'WebAuthn.getCredentials\']'. Without the handler: only ['WebAuthn.getCredentials']. A script over all zendriver.cdp modules showed which <Domain>.lower() names fail to resolve. That WebAuthn/FedCm reset their parameters on a param-less enable is inferred from the CDP spec defaults and was not observed directly in headless mode.
- finder repro idea: Probe probe_domain.py: send network.enable() and web_authn.enable(enable_ui=False), print tab.manually_enabled_domains, add a virtual authenticator, add a CredentialAdded handler, wrap tab.websocket.send to record methods, then send web_authn.get_credentials(id).
