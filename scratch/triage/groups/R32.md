# Group R32 (element-screenshot)

queue: report  |  triage severity: hang  |  triage fix kind: local

## Claim
Element screenshots: Position uses fixed quad indices so mirrored/rotated elements give negative width and Page.captureScreenshot never answers (hang); scrolled pages capture the wrong region; save_screenshot(format='jpg') sends an invalid format

## Files
zendriver/core/element.py (Position.__init__, screenshot_b64, save_screenshot)

## Triage fix strategy (a hypothesis, not a requirement)
min/max over quad points; add scroll offset when capture_beyond_viewport; map jpg->jpeg.

## Triage test approach
Real Chromium.

## Members (UNVERIFIED claims from Stage 1 finders or seeded leads; line numbers may be wrong; do not reuse their scripts)

### A8.1: Element.screenshot_b64 hangs forever on mirrored or rotated elements (negative/zero clip width sent to Chrome)
- where (may drift): zendriver/core/element.py:Position.__init__ (used by screenshot_b64):1171
- finder severity: hang
- claim: A page has <div id=mir style='width:100px;height:40px;transform:scaleX(-1)'> (mirrored icons are common; rotate(180deg) and rotate(90deg) hit the same path). `await (await tab.select('#mir')).screenshot_b64()` or save_screenshot(). Position.__init__ reads left/top/right/bottom from fixed quad indices (left=x4, right=x3, top=y2, bottom=y4) instead of min/max over the points. For a mirrored quad x4 > x3, so width = right-left = -100. to_viewport() sends Page.captureScreenshot clip {x:150, width:-100}. Chrome never replies to that command, so the await never returns.
- finder evidence (unverified): probe3.py with real headless Chromium: get_position() -> <Position(x=150, y=50, width=-100, height=40)>; after 45s the task was still pending with stack 'Element.screenshot_b64 ... element.py:860 wait_for=<Transaction method: Page.captureScreenshot status: pending>'. The same capture with a positive width replied at once. For rotate(90deg) Position gave width=0, height=-200 (quad [520,120,520,320,480,320,480,120]).
- finder repro idea: page2.html in scratch dir: #mir with transform:scaleX(-1); run asyncio.wait([mir.screenshot_b64(format='png')], timeout=45) and see it still pending; task.print_stack() shows it parked on the Page.captureScreenshot Transaction.

### A8.2: Element.screenshot_b64 captures the wrong region when the page is scrolled
- where (may drift): zendriver/core/element.py:screenshot_b64:857
- finder severity: wrong-result
- claim: On a page scrolled to scrollY=1100, `await blue.screenshot_b64()` (or save_screenshot) for an element at document y=1200. get_position() returns viewport-relative quads (y=100). That is passed unchanged as the clip, together with capture_beyond_viewport=True, where Chrome reads clip as document coordinates. The capture is of document y=100..200, i.e. whatever is at the top of the page, not the element.
- finder evidence (unverified): probe2.py: unscrolled screenshot centre pixel (0,0,255) (blue, correct). After scrollTo(0,1100): pos=<Position(x=0, y=100, ...)>, screenshot centre pixel (255,0,0), which is the red block. Related cosmetic case: flash() puts its position:absolute dot at viewport coordinates as well, so the dot is misplaced on scrolled pages.
- finder repro idea: page2.html: red 1200px block then a blue 300x100 block. Scroll with window.scrollTo(0,1100), take blue.screenshot_b64(format='png') and decode the centre pixel.

### A8.11: Element.save_screenshot(format='jpg') fails with 'Invalid image format'
- where (may drift): zendriver/core/element.py:save_screenshot / screenshot_b64:861
- finder severity: crash
- claim: `await el.save_screenshot('x.jpg', format='jpg')`. save_screenshot accepts 'jpg' (it maps it to the .jpg extension) but passes it unchanged to screenshot_b64, which sends Page.captureScreenshot(format='jpg'). Chrome accepts only jpeg/png/webp and rejects it. Tab.screenshot_b64 normalizes 'jpg' to 'jpeg'; the Element version does not.
- finder evidence (unverified): probe2.py: '[R save_screenshot jpg] EXC ProtocolException: Invalid image format command:Page.captureScreenshot params:{\'format\': \'jpg\', ...} [code: -32602]'. tab.py screenshot_b64 lines ~1503-1506 do the jpg->jpeg mapping.
- finder repro idea: page2.html: blue.save_screenshot(path, format='jpg').
