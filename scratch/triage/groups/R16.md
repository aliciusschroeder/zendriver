# Group R16 (connection-close-state)

queue: report  |  triage severity: hang  |  triage fix kind: local

## Claim
Connection state after close (seeded leads + wait()): ConnectionClosed does not reset websocket so aopen never reconnects; aclose() during an in-progress connect is a no-op and the socket opens afterwards; a cancelled send() leaves its Transaction in mapper; Connection.wait() hangs forever on a listener that was cancelled/stopped while busy

## Files
zendriver/core/connection.py (Listener.listener_loop, aopen, aclose, send, wait)

## Triage fix strategy (a hypothesis, not a requirement)
Reset websocket/listener state on ConnectionClosed; make aclose cancel or mark an in-progress open; pop the tx on cancellation; make wait() stop waiting when the listener is no longer running.

## Triage test approach
Browser-free fake websocket / fake server.

### B14.5: Connection.wait() / await tab / Tab.get hang forever when the listener is cancelled while waiting for idle
- where (may drift): zendriver/core/connection.py:Connection.wait:579
- finder severity: hang
- claim: A task runs `await tab` or `await tab.wait()` (Tab.get(url) also ends in self.wait()) while the page is busy, so idle is clear. Then the tab's session goes away: the tab is closed (Target.closeTarget, window.close(), or tab.close() from another task), or the browser websocket closes. The browser listener calls session._detach_session(), which cancels the session Listener, and on ConnectionClosed the listener just breaks out of its loop. A cancelled listener never sets its `idle` Event again, and wait() does `await self.listener.idle.wait()` on that dead listener's Event with no timeout and no done check. The coroutine stays pending forever instead of returning or raising.
- finder evidence (unverified): probe_wait_detach2.py: 'close=False: tab.wait() returned after 1.12s'. 'close=True: tab.wait() still pending after 8.30s -> HANG (listener done=True, session_id=None)'. Task stack: Connection.wait at connection.py:579 `await self.listener.idle.wait()`.
- finder repro idea: Real Chromium: add a ConsoleAPICalled handler and start a ~1s console.log interval. Start asyncio.create_task(tab.wait()). After 0.3s send Target.closeTarget for the tab. Assert the waiter finishes within a few seconds. Control case without the close returns after about 1.1s.
