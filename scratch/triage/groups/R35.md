### A2.5: Headless UA override (and expert shadow-root patch) is applied lazily on the first send, so Browser.get(new_tab=True)/create_context load their first page as 'HeadlessChrome'
- where (may drift): zendriver/core/connection.py:Connection.send / Connection._prepare_headless:641
- finder severity: wrong-result
- claim: browser = await zd.start(headless=True); await browser.get('http://site/new-tab', new_tab=True). Browser.get sends Target.createTarget(url) on the browser connection, so the new tab starts navigating at once. _prepare_headless runs only inside the first send() made on that Tab, which happens after the document request has gone out. The server receives User-Agent '... HeadlessChrome/141...' (and page JS that runs during load sees it as well). The same applies to Browser.create_context(url) (browser.py:511), to popups or target=_blank tabs, and to _prepare_expert's attachShadow patch, which is missing from the first document of those tabs.
- finder evidence (unverified): probe_ua.py printed: '/main-tab False ...Chrome/141...', '/new-tab True ...HeadlessChrome/141.0.0.0...', and after a reload '/new-tab False ...Chrome/141...'.
- finder repro idea: Run a local http.server that records the User-Agent header. Call browser.get(base+'/main-tab'), then browser.get(base+'/new-tab', new_tab=True). The /new-tab document request carries HeadlessChrome. A reload afterwards does not.
