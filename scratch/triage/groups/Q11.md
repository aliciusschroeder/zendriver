### A6.1: wait_for_ready_state uses equality, so the default until='interactive' times out on a page that is already 'complete'
- where (may drift): zendriver/core/tab.py:Tab.wait_for_ready_state (_poll):1343
- finder severity: wrong-result
- claim: tab = await browser.get(fast_url); await tab.wait_for_ready_state() (default until='interactive'). Browser.get returns once navigation starts, and a fast page is already 'complete' by the first poll. _poll checks `ready_state == until`. 'complete' never equals 'interactive' and readyState never goes backwards, so the call polls for the full timeout and then raises TimeoutError('time ran out while waiting for load page until interactive'), even though the page passed 'interactive' long ago. until='loading' fails the same way on any page that is no longer loading.
- finder evidence (unverified): probe1.py against real headless Chromium: 'readyState: complete' then '[wait_for_ready_state default(interactive) on complete page] EXC in 3.00s -> TimeoutError: time ran out while waiting for load page until interactive' and '[wait_for_ready_state loading on complete page] EXC in 2.00s -> TimeoutError'.
- finder repro idea: tab = await browser.get(file_url); await asyncio.sleep(1); assert await tab.evaluate('document.readyState') == 'complete'; await tab.wait_for_ready_state(timeout=3)  # raises TimeoutError after 3s. Fix: compare ordinal ranks (loading < interactive < complete) with >=.
