# Group R24 (remote-needs-local-chrome)

queue: report  |  triage severity: crash  |  triage fix kind: local

## Claim
Connecting to an existing/remote browser (host+port) requires a local Chrome binary because Config.__init__ always runs find_executable

## Files
zendriver/core/config.py (__init__)

## Triage fix strategy (a hypothesis, not a requirement)
Defer executable lookup when host and port are given.

## Triage test approach
Browser-free: PATH without chrome, Config(host=..., port=...) does not raise.

## Members (UNVERIFIED claims from Stage 1 finders or seeded leads; line numbers may be wrong; do not reuse their scripts)

### A3.9: Connecting to an existing or remote browser (host+port) fails with FileNotFoundError when no local Chrome is installed
- where (may drift): zendriver/core/config.py:Config.__init__ (via util.start / Browser.create / create_from_undetected_chromedriver):89
- finder severity: crash
- claim: In a container without Chrome, run `await zd.start(host='chrome-host', port=9222)` against a running DevTools endpoint. Browser.create/util.start build Config(...), and Config.__init__ calls find_executable(browser) whenever browser_executable_path is not given. find_executable raises FileNotFoundError('could not find a valid browser binary'). Browser.start deliberately skips the executable check when connect_existing (`if not connect_existing:` at browser.py:537), but it is never reached. create_from_undetected_chromedriver (`Config()`) fails the same way when Chrome is not in a standard location.
- finder evidence (unverified): probe_remote.py with the default PATH (no chrome): 'zd.start(host, port) raised FileNotFoundError could not find a valid browser binary...'. With chromium on PATH, the same call connects fine.
- finder repro idea: Launch chromium by absolute path with --remote-debugging-port=9557. With PATH not containing any chrome binary, run `await zd.start(host='127.0.0.1', port=9557)` and observe FileNotFoundError.

### A9.2: Connecting to an existing browser (host+port) still requires a local Chrome binary: Config.__init__ autodetects the executable unconditionally
- where (may drift): zendriver/core/config.py:Config.__init__:89
- finder severity: crash
- claim: On a machine with no local Chrome (for example a client talking to a remote or dockerised Chrome), call await zendriver.start(host='127.0.0.1', port=9222), or Browser.create(host=..., port=...) or create_from_undetected_chromedriver. Config.__init__ calls find_executable(browser) whenever browser_executable_path is falsy, and that raises FileNotFoundError('could not find a valid browser binary...'). The call fails before any connection attempt. Browser.start deliberately skips its executable check when connect_existing is true, and the start() docstring says no local browser is started in this case. Passing a bogus browser_executable_path makes the same connection succeed, which shows the binary is never needed.
- finder evidence (unverified): Probe output: 'start(host, port) raised: FileNotFoundError could not find a valid browser binary...' followed by 'with a bogus browser_executable_path it connects fine: Chrome/141.0.7390.37'. Browser.start (browser.py ~530-556) wraps the executable existence check in `if not connect_existing`.
- finder repro idea: Probe probe_remote.py: launch chromium manually with --remote-debugging-port=P. Set PATH=/usr/bin:/bin (no chromium on it) and call zd.start(host='127.0.0.1', port=P), which raises. Then call zd.start(host=..., port=P, browser_executable_path='/does/not/exist'), which connects.

### B16.12: Connecting to an existing browser (host+port) still requires a local Chrome binary
- where (may drift): zendriver/core/config.py:Config.__init__:90
- finder severity: crash
- claim: From a slim container without Chrome, a user connects to a remote or dockerized Chrome with zd.start(host='127.0.0.1', port=9222). The docstring of util.start says 'if both host and port are provided, zendriver will not start a local chrome browser!'. Config.__init__ still calls find_executable(browser) whenever browser_executable_path is unset, which raises FileNotFoundError 'could not find a valid browser binary'. create_from_undetected_chromedriver calls Config() and has the same problem.
- finder evidence (unverified): Probe p9_remote.py with PATH=/usr/bin:/bin: 'connect to existing browser failed: FileNotFoundError could not find a valid browser binary...'. With chromium on PATH, the same call connects.
- finder repro idea: Launch chromium with --remote-debugging-port=P, then run zd.start(host, P) under PATH=/usr/bin:/bin.
