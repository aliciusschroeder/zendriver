# Group Q8 (contradict-shadowing)

queue: fix  |  triage severity: crash  |  triage fix kind: local

## Claim
ContraDict lets a stored key shadow dict methods (clear/get/items/values/update/...), so Element.update/repr/get, Tab.get_all_urls etc. crash on elements with attributes like <br clear="all"> or items=...

## Files
zendriver/core/_contradict.py (ContraDict.__getattribute__)

## Triage fix strategy (a hypothesis, not a requirement)
Resolve real attributes/methods of the class before falling back to keys, as the docstring promises.

## Triage test approach
Browser-free: ContraDict({'clear': 'all', 'items': '3', 'get': 'x'}) -> .clear(), .items(), .get('x') still work and attribute access to non-method keys still returns values; Element with a 'clear' attribute can update()/repr.

## Members (UNVERIFIED claims from Stage 1 finders or seeded leads; line numbers may be wrong; do not reuse their scripts)

### A11.1: ContraDict lets a stored key hide dict methods, so Element.update/get/repr and Tab.get_all_urls crash on attributes named clear/get/items
- where (may drift): zendriver/core/_contradict.py:ContraDict.__getattribute__:53
- finder severity: crash
- claim: __getattribute__ returns self[attribute] whenever the attribute name is a key (line 53). It checks this before the _check_key warning-name guard, so a key named clear/get/items/values/keys/update/pop/copy replaces the bound dict method. The class docstring says the opposite ('names like keys, update, values won't overwrite the methods'). Element._attrs is a ContraDict filled from the DOM attributes. Public paths that break: (1) `br = await tab.select('br')` on `<br clear="all">` (a legacy attribute that is still common), then `await br`, `br.update()`, `br.query_selector(...)`, save_to_dom or remove_from_dom. update() calls self.attrs.clear() at element.py:334, so this is `"all"()` and raises TypeError. (2) An element with an `items` attribute (common on web components, e.g. `<my-list items='[1,2]'>`): str() or repr() of it, or of any ancestor, since __repr__ recurses into children (element.py:1160 attrs.items()), raises TypeError. Tab.get_all_urls() (tab.py:1629) raises the same way when an a/link/img/script/meta element has `items`. (3) An element with a `get` attribute: elem.get(name), elem[name] and elem.<anything> through __getattr__ all raise TypeError (element.py:239/265); so does cloudflare's challenge_iframe.attrs.get('style'). (4) The ContraDict returned by Element.get_js_attributes() for a <br> has a 'clear' key, so js.clear() raises. The same happens with cdict({'keys':1}).keys().
- finder evidence (unverified): Real headless Chromium probe (scratch elem_probe.py, elem_probe2.py): `await br.update()` -> TypeError 'str' object is not callable; br.query_selector('x') -> TypeError; repr(<a items=3>) -> TypeError; tab.get_all_urls() -> TypeError; s.get('id'), s['id'] and s.id -> TypeError; svg animate attrs.values() -> TypeError; str(div wrapping <my-list items=...>) -> TypeError; get_js_attributes() of <br> then .clear() -> TypeError. Pure probe (cd_probe.py): cd.keys(), cd.items(), cd.clear(), cd.get('a') and cd.values() all raise TypeError. This behaviour predates the repo history (dd9a4f8 only added type hints).
- finder repro idea: Load data:text/html,<body><div id=wrap><my-list items='[1,2]'></my-list></div><br id=b clear=all><span id=s get=g></span></body>. Then `await (await tab.select('#b')).update()` gives TypeError; `str(await tab.select('#wrap'))` gives TypeError; `(await tab.select('#s')).get('id')` gives TypeError. Pure-Python version: ContraDict({'clear':'all'}, silent=True).clear() gives TypeError.

### B16.15: An HTML attribute named clear/items/get/update/... shadows the ContraDict method, crashing Element.update(), repr() and get()
- where (may drift): zendriver/core/_contradict.py:ContraDict.__getattribute__:53
- finder severity: crash
- claim: The ContraDict docstring says names like 'keys', 'update', 'values' 'won't overwrite the methods'. Its __getattribute__ returns self[attribute] first, though, so an element whose attributes include one of these names breaks the methods zendriver calls on Element.attrs. Examples: a legacy <br clear="all"> (await elem / elem.update() / elem.query_selector_all() call self.attrs.clear() and raise TypeError: 'str' object is not callable); a custom element <x-list items="..."> (repr(elem), str(elem) and save_to_dom call attrs.items()); an attribute named get (elem.get('id') calls attrs.get()).
- finder evidence (unverified): In-memory probe: "['clear', 'all'] -> TypeError 'str' object is not callable", "['items', '[1,2]'] -> TypeError 'str' object is not callable" (repr), "['get', 'x', 'id', 'a'] -> TypeError 'str' object is not callable".
- finder repro idea: Build an Element with attributes ['clear','all'], ['items','x'] and ['get','x'], then call attrs.clear(), repr() and get('id').
