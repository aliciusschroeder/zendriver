### A9.8: circle() replaces y=0 with x (and is centred at (x-2r, y-2r)), so the documented demo traces the wrong path for a window at the top of the screen
- where (may drift): zendriver/core/util.py:circle:219
- finder severity: wrong-result
- claim: zd.util.circle(100, 0, radius=10) (examples/demo.py calls util.circle(*center) with center=(window.left, window.top), and top is 0 for a window at the top of the screen). `if not y: y = x` treats 0 as missing, so the points are computed around y=100-2r instead of y=0-2r. A separate oddity: the circle is centred at (int(x-2r), int(y-2r)), not at (x, y).
- finder evidence (unverified): Probe: circle(100, 0) gave [(80.0, 90.0), (90.0, 80.0), (80.0, 70.0), (70.0, 80.0), (80.0, 90.0)], with y around 80 instead of around -20. circle(100, 50) gave y around 30, so the circle is centred at (x-2r, y-2r).
- finder repro idea: list(util.circle(100, 0, radius=10, num=4)) and look at the y values.

### A9.9: html_from_tree emits every subtree's HTML again after the parent's outer HTML
- where (may drift): zendriver/core/util.py:html_from_tree:250
- finder severity: wrong-result
- claim: doc = await tab.send(cdp.dom.get_document(-1, True)); html = await zd.util.html_from_tree(doc, tab) on a page '<p>hello</p>'. For each child it appends get_outer_html (which already includes all descendants) and then recurses into that child, appending the descendants' outer HTML again at every depth. A depth-d node therefore shows up d times.
- finder evidence (unverified): Probe output: html_from_tree(document) = '<html><head></head><body><p>hello</p></body></html><head></head><body><p>hello</p></body><p>hello</p>hello' ('hello' appears 4 times), while tab.get_content() = '<html><head></head><body><p>hello</p></body></html>'.
- finder repro idea: Probe probe_html.py: data:text/html,<p>hello</p>, then compare html_from_tree(doc) with tab.get_content().

### A9.7: add_extension(dir) loads the last nested 'manifest.*' match instead of the extension root
- where (may drift): zendriver/core/config.py:Config.add_extension:187
- finder severity: wrong-result
- claim: config.add_extension('/path/my_ext'), where my_ext/manifest.json is the real manifest and the extension also ships a nested file matching manifest.* (for example web/manifest.webmanifest, or a bundled page's assets/manifest.json). The loop `for item in path.rglob('manifest.*'): path = item.parent` keeps overwriting path, ending on the last (nested) match. Browser.start then passes --load-extension=/path/my_ext/web, a directory that is not the extension, and Chrome fails to load it.
- finder evidence (unverified): Probe output: 'I: extension root .../tmphfn8k9y1 -> loaded path [PosixPath(\'.../tmphfn8k9y1/web\')]'.
- finder repro idea: Make a temp dir with manifest.json at the root and web/manifest.webmanifest, call add_extension(dir), and print config._extensions.

### A9.11: add_extension(.crx) extracts into a mkdtemp directory that is never removed
- where (may drift): zendriver/core/config.py:Config.add_extension:181
- finder severity: leak
- claim: config.add_extension('ext.crx'); browser = await zd.start(config); await browser.stop(). The crx is extracted into tempfile.mkdtemp(prefix='extension_'). Nothing in config.py or browser.py tracks or deletes it: Browser cleanup removes only the profile dir. Every script run or Config that adds a packed extension leaves a full copy of the extension in /tmp.
- finder evidence (unverified): Probe output: 'extracted dir /tmp/extension_ny3ne2z031b4e071 still exists after browser.stop(): True'. grep: the only rmtree in zendriver/core is browser.py:927, and it removes only config.user_data_dir.
- finder repro idea: Probe probe_crx.py: zip a manifest.json into ext.crx, add_extension, start and stop a headless browser, then check os.path.isdir(config._extensions[0]).

### B16.17: Config.add_extension leaves the temp directory it extracts each .crx into
- where (may drift): zendriver/core/config.py:Config.add_extension:181
- finder severity: leak
- claim: config.add_extension('ext.crx') extracts the archive into tempfile.mkdtemp(prefix='extension_'). Nothing ever removes that directory: Browser._stop and _cleanup_temporary_profile only rmtree user_data_dir. Each call, for example one Config per job in a long-running service, leaves one extracted copy in /tmp.
- finder evidence (unverified): Code reading: grep shows no cleanup for the 'extension_' temp dirs, and _extensions holds only the paths. Not probed.
- finder repro idea: Zip a minimal manifest.json into a .crx, call add_extension, start and stop a browser, and look for /tmp/extension_*.
