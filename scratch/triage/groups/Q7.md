# Group Q7 (register-handlers-snapshot)

queue: fix  |  triage severity: crash  |  triage fix kind: local

## Claim
Connection._register_handlers raises ValueError (list.remove(x): x not in list) when a nested send changed enabled_domains after the snapshot, so the user's command is never sent

## Files
zendriver/core/connection.py (_register_handlers)

## Triage fix strategy (a hypothesis, not a requirement)
Only remove stale domains that are still present (or recompute against the live list after the awaits).

## Triage test approach
Browser-free fake websocket: auto-enable network via a handler, swap the handler for one of another domain, send -> no ValueError; enabled_domains converges.

### A2.1: _register_handlers raises ValueError (and the user's command is never sent) when a stale auto-enabled domain and a new handler domain are handled in the same pass
- where (may drift): zendriver/core/connection.py:Connection._register_handlers:720
- finder severity: crash
- claim: tab.add_handler(cdp.network.RequestWillBeSent, h); await tab.send(cdp.runtime.evaluate('1'))  # Network auto-enabled. Then tab.remove_handlers(cdp.network.RequestWillBeSent, h); tab.add_handler(cdp.log.EntryAdded, h2); await tab.send(cdp.runtime.evaluate('1+1')) -> ValueError: list.remove(x): x not in list. The same thing happens with public helpers: `async with tab.expect_request(url): await tab.reload()` (its network handlers remove themselves), then tab.add_handler(cdp.page.LoadEventFired, cb); await tab.reload() -> ValueError. Trace: send -> aopen -> RH#1 copies enabled_domains=[network]. It finds log not enabled, appends it and awaits send(Log.enable,_is_update=True). That send calls aopen -> RH#2 (nested). RH#2 sees network has no handlers and removes it from self.enabled_domains. RH#1 resumes, and its cleanup loop `for ed in enabled_domains: self.enabled_domains.remove(ed)` removes network a second time, outside any try.
- finder evidence (unverified): Probe probe_stale.py printed '2nd send raised: ValueError list.remove(x): x not in list' with traceback send:632 -> aopen:458 -> _register_handlers:720. Probe probe_stale2.py (expect_request then add LoadEventFired handler then tab.reload()) printed 'tab.reload() raised ValueError list.remove(x): x not in list'. The failure is deterministic and the next send succeeds.
- finder repro idea: Real headless Chromium: add a network handler, send once, remove it, add a handler for any domain that is not enabled yet (log/page), send again. Expect no exception. A fix is to skip an `ed` that is no longer in self.enabled_domains, or to stop running RH from inside the nested enable send.
