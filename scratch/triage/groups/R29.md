# Group R29 (dom-misc-crashes)

queue: report  |  triage severity: crash  |  triage fix kind: local

## Claim
DOM query crashes/error swallowing: filter_recurse_all yields raw cdp Nodes for shadow roots (AttributeError in find on iframe shadow DOM); Tab.query_selector crashes on cross-origin iframes (content_document None); element-scoped query_selector(_all) swallow every ProtocolException except 'could not find node'; element-scoped query results get the container Element as tree/node so .parent is None

## Files
zendriver/core/util.py, zendriver/core/tab.py (query_selector, query_selector_all, find_elements_by_text)

## Triage fix strategy (a hypothesis, not a requirement)
Wrap shadow roots consistently; add the None guard; re-raise unexpected ProtocolExceptions.

## Triage test approach
Real Chromium pages.

## Members (UNVERIFIED claims from Stage 1 finders or seeded leads; line numbers may be wrong; do not reuse their scripts)

### A6.2: find/find_all/find_elements_by_text crash with AttributeError when matching text is inside a shadow root in a same-origin iframe (including the user-agent shadow DOM of <input placeholder>)
- where (may drift): zendriver/core/tab.py:Tab.find_elements_by_text (iframe branch):765
- finder severity: crash
- claim: The page has a same-origin iframe (srcdoc or same-origin src) containing <input placeholder='Search needle'> or an element with an open shadow root holding the text. Calling await tab.find('needle'), tab.find_all('needle'), tab.wait_for(text='needle') or tab.find_elements_by_text('needle') reaches the iframe branch, which calls util.filter_recurse_all(iframe_elem, pred). Called on an Element, filter_recurse_all yields Element children, but for children that have shadow roots it recurses into child.shadow_roots[0], a raw cdp.dom.Node, and appends raw cdp Nodes to the result. Line 765 then evaluates `element.create(text_node.node, ...)` on a cdp.dom.Node and raises AttributeError: 'Node' object has no attribute 'node'. find() and find_all() do not catch it, so the whole lookup fails, and keeps failing on every retry.
- finder evidence (unverified): probe1.py/probe2.py against headless Chromium: '[iframe_input find_elements_by_text] EXC -> AttributeError: 'Node' object has no attribute 'node'', '[iframe_input find('needle')] EXC -> AttributeError', '[iframe_input find_all('needle')] EXC -> AttributeError', '[find(shadow needle)] EXC -> AttributeError'. Traced through util.filter_recurse_all lines 158-160: shadow_roots[0] is a cdp.dom.Node, but the caller treats every result as an Element.
- finder repro idea: Page: <iframe srcdoc="<input placeholder='Search needle'>"></iframe>; await tab.find_elements_by_text('needle') -> AttributeError. Also: same-origin iframe src containing a div with attachShadow({mode:'open'}).innerHTML='<b>shadow needle</b>'; await tab.find('shadow needle') -> AttributeError.

### A5.3: Element.query_selector on a cross-origin (out-of-process) iframe crashes with AttributeError instead of returning None
- where (may drift): zendriver/core/tab.py:Tab.query_selector:641
- finder severity: crash
- claim: `iframe = await tab.select('#cross-frame')` (iframe src on another site, so Chrome runs it out of process and content_document is None). Then `await iframe.query_selector('p')`: Element.query_selector calls tab.query_selector(selector, self). There `_node.node_name == 'IFRAME'`, so `doc = _node.content_document` is None, and line 646 evaluates `doc.node_id`, raising AttributeError: 'NoneType' object has no attribute 'node_id'. The except only catches ProtocolException, so it propagates. query_selector_all received the guard `if doc is None: return []` (line 556-557, 'cross-origin iframes block access to content_document, skip gracefully'), but query_selector did not.
- finder evidence (unverified): Probe output: 'cross content_document: None', '[cross.query_selector_all] -> []', '[cross.query_selector] EXC AttributeError: 'NoneType' object has no attribute 'node_id''.
- finder repro idea: The cross_site_iframe_url fixture: iframe = await tab.select('#child-frame'); await iframe.query_selector('p') raises AttributeError. Probe: scratchpad/detect-A5/probe1.py.

### A5.8: Element-scoped query_selector/query_selector_all swallow every ProtocolException except 'could not find node' (invalid selector -> []/None) while the tab-level calls raise
- where (may drift): zendriver/core/tab.py:Tab.query_selector_all / Tab.query_selector:576
- finder severity: wrong-result
- claim: `await (await tab.select('#top')).query_selector_all('a[[')` returns [] and `.query_selector('a[[')` returns None, but `tab.query_selector_all('a[[')` raises ProtocolException 'DOM Error while querying'. In the except block, the `if _node is not None:` branch handles only messages containing 'could not find node' and has no else/raise. Any other error (bad selector, 'target session was detached', 'connection was closed' arriving during the query) falls through to `if not node_ids: return []`, and disable_dom_agent is skipped. A typo in a selector looks like 'no match'.
- finder evidence (unverified): Probe: '[tab.query_selector_all invalid] EXC ProtocolException: DOM Error while querying ... [code: -32000]', '[elem.query_selector_all invalid] -> []', '[elem.query_selector invalid] -> None', '[tab.query_selector invalid] EXC ProtocolException ...'.
- finder repro idea: top = await tab.select('#top'); with pytest.raises(ProtocolException): await top.query_selector_all('a[[') fails because it returns []. Probe: scratchpad/detect-A5/probe1.py.

### B15.7: Element.query_selector_all / query_selector silently swallow every ProtocolException except 'could not find node' (e.g. invalid selector -> [] / None)
- where (may drift): zendriver/core/tab.py:Tab.query_selector_all / Tab.query_selector (the _node branch, reached from Element.query_selector_all / Element.query_selector):576
- finder severity: wrong-result
- claim: `box = await tab.select('#box'); await box.query_selector_all('span[[')` returns [], and box.query_selector('span[[') returns None. In the `except ProtocolException` handler, the `_node is not None` branch only handles 'could not find node' and has no else/raise. Any other DOM error falls through to `if not node_ids: return []` (or `return None`). A selector typo or any other DOM error therefore looks like 'no such element', silently, for element-scoped queries.
- finder evidence (unverified): probe_swallow.py printed: 'tab.query_selector_all invalid -> raises ProtocolException: DOM Error while querying', 'box.query_selector_all invalid -> []', 'box.query_selector invalid -> None'. The query_selector equivalent is at tab.py:649.
- finder repro idea: Compare tab.query_selector_all('span[[') (raises) with (await tab.select('#box')).query_selector_all('span[[') (returns []). Probe: /tmp/claude-0/-home-user-zendriver/b2021b39-94e6-5220-9e66-7f33c0314a80/scratchpad/detect-B15/probe_swallow.py

### A8.8: Results of Element.query_selector(_all) have .parent None for anything at or above the queried element, and .node is an Element
- where (may drift): zendriver/core/element.py:query_selector / query_selector_all / parent:834
- finder severity: wrong-result
- claim: `outer = await tab.select('#outer'); inner = await outer.query_selector('#inner'); inner.parent` returns None, although #inner's parent is #outer. Element.query_selector passes `self` as _node. Tab.query_selector then runs filter_recurse over the Element (so it returns a child *Element*, wrapped again by create()) and sets tree=the container Element. parent searches self.tree with filter_recurse, which never tests the root, so the queried element and its ancestors are unreachable. For #bold (outer>p>b), bold.parent is <p> but bold.parent.parent is None. inner.node is an Element rather than a cdp.dom.Node.
- finder evidence (unverified): probe1.py: '[E] inner type node: Element tree type: Element', '[E] inner.parent -> None', '[E] inner2.parent (doc query) -> <div id="outer">...', '[E] bold.parent -> <p id="deep">... bold.parent.parent -> None'.
- finder repro idea: page1.html: outer.query_selector('#inner').parent, and compare it with (await tab.query_selector('#inner')).parent.
