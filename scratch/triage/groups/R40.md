## Members (UNVERIFIED claims from Stage 1 finders or seeded leads; line numbers may be wrong; do not reuse their scripts)

### A6.6: set_window_size / set_window_state(state='normal') ignore the requested bounds when the window is maximized, minimized or fullscreen
- where (may drift): zendriver/core/tab.py:Tab.set_window_state:1201
- finder severity: wrong-result
- claim: await tab.maximize() (or minimize()/fullscreen()), then await tab.set_window_size(200, 100, 900, 700). For the normal state, set_window_state sends one Browser.setWindowBounds with windowState=normal plus left/top/width/height. When the window is not normal, Chrome only restores it and drops the geometry. The code handles the reverse case ('min, max, full can only be used when current state == NORMAL') but not this one. The window ends up at 0,0 1280x720 instead of 200,100 900x700, and no error is raised.
- finder evidence (unverified): probe10.py headless: 'C set_window_size(200,100,900,700) after maximize: state=normal l=0 t=0 w=1280 h=720', and the same after minimize and after fullscreen. probe3.py: '[set_window_size(10,20,900,700) while max] OK' -> 'after size2: state=NORMAL l=0 t=0 w=1280 h=720'.
- finder repro idea: await tab.maximize(); await tab.set_window_size(200,100,900,700); _, b = await tab.get_window(); assert (b.left,b.top,b.width,b.height) == (200,100,900,700)  # fails. Fix: if the current state is not normal, first send Bounds(window_state=NORMAL) with no geometry, then send the geometry.

### A6.7: minimize()/maximize()/fullscreen() first move and resize the window to 0,0 1280x720, losing the user's restore geometry
- where (may drift): zendriver/core/tab.py:Tab.set_window_state:1205
- finder severity: wrong-result
- claim: await tab.set_window_size(100, 50, 800, 600); await tab.maximize(). For any non-normal target state the code first calls `await self.set_window_state(state='normal')` with the default left=0, top=0, width=1280, height=720. On a normal window that call resizes and moves it to 0,0 1280x720 before maximizing. When the window is restored later (a plain Browser.setWindowBounds(windowState=normal), the user un-maximizing in headful mode, or any restore), it comes back at 0,0 1280x720 instead of 100,50 800x600. A raw CDP maximize keeps the geometry. In headful mode the window also visibly jumps and resizes before every minimize, maximize or fullscreen.
- finder evidence (unverified): probe10.py headless: 'A sized: l=100 t=50 w=800 h=600' -> 'A maximized' -> 'A plain restore (no bounds): state=normal l=0 t=0 w=1280 h=720', versus the control 'B raw maximize' -> 'B plain restore: state=normal l=100 t=50 w=800 h=600'. Under Xvfb in headful mode, 'after max: l=0 t=0 w=1280 h=720' right after 'after size: l=10 t=20 w=800 h=600'.
- finder repro idea: set_window_size(100,50,800,600); maximize(); send Browser.setWindowBounds(wid, Bounds(window_state=NORMAL)); get_window() shows 0,0,1280,720. A control run with a raw maximize instead of tab.maximize() restores to 100,50,800,600. Fix: restore with Bounds(window_state=NORMAL) and no geometry.
