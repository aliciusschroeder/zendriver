## Lens: reproduce (verdict confirmed, realism high, severity hang)

### Summary
All three element-screenshot bugs reproduce on real headless Chromium 141 with Python 3.13. (1) Position.__init__ unpacks the quad so that left=x4, right=x3, top=y2 and bottom=y4. A scaleX(-1) element therefore gets width=-100, and a rotate(180deg) element gets width=-100 and height=-40. Page.captureScreenshot with that clip never replies: the task was still pending after 60s, parked in screenshot_b64. (2) On a scrolled page the clip is taken from viewport-relative quads but used with captureBeyondViewport=True, so the wrong region is captured. (3) format='jpg' is passed straight to Chrome and rejected with -32602.

### Refinements
rotate(90deg) leads to width=0 and a Chrome error, not a hang. Only negative width/height hangs (mirrored, rotate(180deg), and probably other flips). The finder's stack line element.py:860 matches. After a hung capture, later captures of the same region can return wrong pixels until the page state resets. Taking min/max over the quad points fixes both the hang and the 0-width case for flips. Rotations other than multiples of 90 degrees also need min/max, since the quad is not axis-aligned.

## Lens: refute (verdict confirmed, realism medium, severity hang)

### Summary
I could not refute any member. Everything was run against real headless Chromium 141 on Python 3.13. Position.__init__ (element.py, class Position) unpacks the quad so that left=x4, top=y2, right=x3 and bottom=y4. For mirrored or rotated elements that gives a negative clip width or height, and Chrome holds a Page.captureScreenshot with a negative clip pending with no time limit. screenshot_b64 passes viewport-relative quads as the clip together with capture_beyond_viewport=True, so on a scrolled page it captures the wrong region. Element.screenshot_b64 passes format='jpg' to Chrome unchanged, and Chrome rejects it.

### Refinements
A8.1 hangs only when width or height is negative. Width or height of exactly 0 (rotate 90deg) raises an error at once. Any rotation steep enough (e.g. 45deg on a 100x40 box) or any mirroring hangs. Small rotations give a positive but wrong-sized clip. The hang ends only when another valid captureScreenshot completes on the same target, which a sequential script never does. Position.center stays correct for mirrored and rotated quads, so mouse_click is unaffected; only the clip is wrong. A8.2 affects every scrolled page, including the result of scroll_into_view.

## Lens: fixsafety (verdict confirmed, realism high, severity hang)

### Summary
All three element-screenshot bugs reproduce on real headless Chromium 141 with Python 3.13. (1) Position.__init__ unpacks fixed quad indices, so left=x4, right=x3, top=y2 and bottom=y4. For transform:scaleX(-1) this gives width=-100, and Element.screenshot_b64 then parks forever on the Page.captureScreenshot Transaction because Chrome never replies. For rotate(90deg) it gives width=0, which Chrome rejects with an error. (2) On a scrolled page the viewport-relative content quad is sent as a document-relative clip (capture_beyond_viewport=True), so the wrong region is captured. (3) Element.screenshot_b64/save_screenshot pass format='jpg' through unchanged and Chrome rejects it. A minimal local fix (bounding box of the quad, add cssVisualViewport.page_x/page_y, map jpg to jpeg) fixes all three.

### Refinements
Only the mirrored case hangs. rotate(90deg) gives a zero width and an immediate Chrome error, not a hang. The scroll bug affects every element once the page is scrolled, including position:fixed and sticky ones. It does not show for below-the-fold elements on an unscrolled page, because viewport and document coordinates are then the same. Calling scroll_into_view() before a screenshot, which is a natural step, triggers it. With fixed indices, Position.center is also wrong for rotated elements (by 20px for the rotate(90deg) quad), which affects mouse_click/mouse_move/flash. The bounding-box fix corrects that too. For scaleX(-1) the centre is the same either way. flash() still positions its dot from viewport coordinates with position:absolute, so it is misplaced on scrolled pages (cosmetic, not fixed here). The hang itself is Chrome not answering a negative-size clip, and Connection.send has no timeout. A raw tab.send(capture_screenshot(clip with negative width)) would still hang.
