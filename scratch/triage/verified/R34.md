## Lens: fixsafety (verdict confirmed, realism high, severity crash)

### Summary
All four attribute-plumbing bugs reproduce browser-free with an in-memory Element, and get('class') also on real Chromium. _make_attrs stores 'class' as 'class_', so get('class') and el['class'] return None. Element.__setattr__ checks key[1:] (for 'tree' it looks up 'ree') instead of '_'+key, so el.tree = doc writes an HTML attribute 'tree' and never reaches the property setter. copy.copy(el) recurses forever, because __getattr__('_attrs') calls get(), which reads self.attrs, which reads self._attrs, and so on. highlight_overlay's getattr(self, '_is_highlighted', False) goes through the @deprecated __getattr__, so it warns, and under warnings-as-errors it raises before sending anything. Small local fixes in element.py fix all of them.

### Refinements
Only copy.copy hits the RecursionError on a real Element. deepcopy and pickle of a real Element fail with TypeError because of the Tab and still do after the fix, which is expected. dataclasses.asdict or deepcopy of a structure holding Elements therefore fails with TypeError, not RecursionError. __setitem__ has the same key[1:] typo. It is harmless for most names but silently drops keys such as 'a_tab', and el['class'] = v adds a second 'class' key beside 'class_', so repr shows class twice. It is left unchanged because switching it to '_'+key would make el['tree'] = x a silent no-op. The fix for A8.15 and A8.16 is shared: __getattr__ must raise AttributeError for '_'-prefixed names before any warning is emitted. This needs the @deprecated decorator replaced by an explicit warnings.warn after the guard, because the decorator warns before the body runs.

### Member verdicts
- A8.12: confirmed — In-memory: get('class') -> None, get('class_') -> 'x y'. On real Chromium, tab.select('#a') with class='x y' also gives get('class') None.
- B16.14: confirmed — el['class'] -> None as well, while repr shows class="x y". Same root cause as A8.12.
- A8.14: confirmed — After el.tree = doc: 'el.tree is doc? False | attrs keys [id, class_, tree]'.
- B16.16: confirmed — Same root cause as A8.14. The bogus 'tree' attribute lands in attrs, so repr() and save_to_dom would write it.
- A8.15: confirmed — copy.copy raises RecursionError, for the in-memory element and for a real Element from Chromium. Refinement: for a real Element, deepcopy and pickle fail earlier with 'TypeError: cannot pickle _thread.lock object' (the Tab's state), before reaching the recursion. They only raise RecursionError when the tab is copyable (fake tab).
- A8.16: confirmed — Without filters, highlight_overlay emits 'Call to deprecated method __getattr__. (Use get() instead)'. With warnings.simplefilter('error', DeprecationWarning) it raises DeprecationWarning and no CDP command is sent (sent == []). By code reading, Tab.query_selector(_all)'s getattr(_node, '__last', None) retry path warns in the same way when given an Element.
