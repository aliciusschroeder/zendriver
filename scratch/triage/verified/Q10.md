### Summary
Confirmed. Tab.__call__ (zendriver/core/tab.py:1952-1966) has the signature (text=None, selector=None, timeout=10) and ends with `return await self.wait_for(text, selector, timeout)`, while Tab.wait_for (tab.py:1284) is declared as wait_for(selector=None, text=None, timeout=10). Because the arguments are passed by position, the text value lands in wait_for's selector and the selector value lands in its text. On real headless Chromium, tab(text=X) and tab(X) send X to query_selector as a CSS selector. If X is not a valid selector (e.g. 'Sign up!'), DOM.querySelector raises ProtocolException at once. It only gets the right element because DOM.performSearch also accepts CSS selectors.

### Refinements
Two outcomes for tab(text=X), depending on X: if X is a valid CSS selector that matches nothing, it polls until the timeout and raises TimeoutError. If X is not a valid selector (contains '!', spaces with punctuation, etc.), query_selector raises ProtocolException at once (and disable_dom_agent is called first). If a text string happens to be a valid selector that matches an element (e.g. tab(text='button')), the call returns the CSS match, not a text match. tab(selector=S) is a text search for S; in my runs ('#p1', 'li', 'button') it still returned the right element because performSearch also accepts selectors. I did not find a selector input where it returns a wrong element. The fix the triage proposes, self.wait_for(selector=selector, text=text, timeout=timeout), is local and keeps the public signature. The docstring ("alias to query_selector_all or find_elements_by_text") is also inaccurate, since it returns a single element through wait_for.

## Lens: refute (verdict confirmed, realism medium, severity wrong-result)

### Summary
I could not refute this. Tab.__call__(self, text=None, selector=None, timeout=10) (zendriver/core/tab.py, Tab.__call__, line 1966) ends with `return await self.wait_for(text, selector, timeout)`. Those arguments are positional, but the signature is Tab.wait_for(self, selector=None, text=None, timeout=10) (line 1284). So the text goes into the selector slot and the selector goes into the text slot. I reproduced it with real headless Chromium on Python 3.13: tab(text=...) and tab('...') run DOM.querySelector on the text. For plain words this polls until the timeout and raises TimeoutError. For text that is not a valid selector, such as 'Sign up!', it raises ProtocolException at once. tab(selector=...) runs DOM.performSearch on the selector. That returns the same element as wait_for(selector=...) when the CSS selector matches. When it does not match, it returns a wrong element (any node whose text contains the selector string) instead of waiting or raising.

### Refinements
1. tab(text=X) and positional tab(X) never use the text search first. If X is a valid but non-matching selector, the call always waits the full timeout and then raises TimeoutError. If X is not a valid CSS selector (contains '!', starts with a digit, and so on), it raises ProtocolException at once.
2. tab(selector=S) is not merely 'works by luck'. If the CSS matches, it returns the same element, but through the slower find_elements_by_text path, which fetches the whole document and runs performSearch. If the CSS does not match yet, it returns a false positive: any element whose text, tag name or attribute contains S (verified: 'li' matched a <span>linkedin</span>). So code that uses tab(selector=...) to wait for an element can return immediately with the wrong element.
3. With both arguments, the text is polled as CSS for the whole timeout before the selector is tried as text.
4. Severity is wrong-result, not crash. Python-version independent (pure argument-order bug).

## Lens: fixsafety (verdict confirmed, realism high, severity wrong-result)

### Summary
Tab.__call__(self, text=None, selector=None, timeout=10) at zendriver/core/tab.py:1966 returns `await self.wait_for(text, selector, timeout)`, passing its arguments by position. The signature is Tab.wait_for(self, selector=None, text=None, timeout=10) (tab.py:1284), so the two arguments land in each other's slots. tab(text=X) and tab(X) run query_selector(X) as CSS. If X is not a valid selector this fails at once, and otherwise it polls until the timeout. tab(selector=S) runs find_element_by_text(S). It works only because DOM.performSearch also accepts CSS. I reproduced this on real headless Chromium and fixed it in a one-line prototype: `return await self.wait_for(selector=selector, text=text, timeout=timeout)`.

### Refinements
1) Severity is wrong-result for all members. A12.1's 'crash' is overstated, though the ProtocolException path is real: text that is an invalid CSS selector fails at once with ProtocolException instead of TimeoutError. 2) tab(selector=...) is not fully OK on repo code either. It runs a text search, so a selector string that also appears as page text, or a selector performSearch handles differently, can return a different element than query_selector would. It also skips the CSS path's stale-document retry. 3) The docstring ('alias to query_selector_all or find_elements_by_text') is inaccurate: the method waits for and returns a single Element. Fixing it is optional and cosmetic. 4) Be careful with data: URLs in tests: a '#' in the HTML truncates the page as a URL fragment. My first positional probe was invalidated by this and rerun without '#'.
