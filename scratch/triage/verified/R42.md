### Summary

The Listener's ConnectionClosed path passes the websockets exception instance, which is shared but not mutated, because send only catches ProtocolException. A1.3 loses only the one command; the connection keeps working. Group severity is set to hang because of A1.3; the other members are wrong-result or cosmetic.

## Lens: refute (verdict confirmed, realism low, severity hang)

### Summary
All four issues reproduce. (1) _fail_pending_transactions sets one ProtocolException object on every pending tx, and each Connection.send's `e.message +=` mutates that shared object. Every caller gets the same object, listing all the other commands and their params. (2) NaN or Infinity params produce invalid JSON. Chrome replies with an id-less -32700 error on the browser websocket, and send() hangs with the tx left in mapper. (3) remove_handlers(module[, handler]) silently does nothing. (4) ProtocolException.__str__ drops the CDP error 'data' field. The NaN hang is the only severe member, and its realism is low. The rest are cosmetic or API-asymmetry issues.

### Refinements
Shared exception: needs two or more sends pending when aclose() / _detach_session runs (browser.stop(), tab close, Target.detachedFromTarget). It is cosmetic: the error text names the wrong commands and other calls' params. NaN: only user-supplied non-finite floats (numpy data, math.inf); zendriver's own computed coordinates are finite. remove_handlers(module): outside the type-annotated contract. 'data' drop: cosmetic, but it hits anyone debugging bad params.

## Lens: fixsafety (verdict confirmed, realism medium, severity hang)

### Summary

Every caller gets the same object, listing all the commands and their params, including another call's token URL. (2) Transaction.message uses json.dumps with allow_nan=True.
