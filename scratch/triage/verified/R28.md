## Lens: reproduce (verdict confirmed, realism high, severity wrong-result)

### Summary
util.filter_recurse (util.py:173) and filter_recurse_all (util.py:139) walk only .children and .shadow_roots[0], never .content_document. Elements inside same-origin iframes therefore cannot be found again after Element.update() (element.py:293). They lose .parent, keep a stale node_id (so element-scoped queries silently return []/None), remove_from_dom() does nothing without raising, and text search returns a parentless #text node plus a duplicate of its parent. All 6 members reproduced on real headless Chromium 141.

### Refinements
The root cause is confirmed exactly as stated. Element.update() also replaces _tree with the top document even when the node is not found, so the element's real tree is lost. Separately, Element.update() does not refresh node_id when the lookup misses, and that is what turns the frame blind spot into silent []/None for scoped queries (via the __last one-shot retry in Tab.query_selector(_all)). A5.5(b) (container-scoped results get the container Element as node/tree) is a different root cause from the iframe one, and it is the same bug as R29/A8.8. Dedup across groups.

## Lens: refute (verdict confirmed, realism medium, severity wrong-result)

### Summary
I tried to refute this and could not. util.filter_recurse (util.py:173) and filter_recurse_all (util.py:139) only walk .children and shadow_roots[0]. With pierce=True, Chrome reports an IFRAME's document under .content_document and leaves the IFRAME's .children empty, so the helpers never reach a same-origin iframe's DOM. As a result Element.update() (element.py:293, filter_recurse at :323), Element.parent (:360), remove_from_dom (:279), the Tab.query_selector_all include_frames results (tab.py:615, created with tree=top doc) and the find_elements_by_text main loop (tab.py:715) all lose iframe nodes. All 6 members reproduced on headless Chromium 141 with Python 3.13.

### Refinements
Only same-origin (in-process) iframes are affected; cross-origin iframes have content_document=None and are a separate path. Elements obtained through iframe.query_selector work until something calls update(): an explicit update(), `await elem`, elem.query_selector(_all), set_text, save_to_dom or remove_from_dom. click() does not call update(), so plain clicks on such elements still work. Elements from select_all/select(include_frames=True) have parent None straight away. Text search only goes wrong for find_all, find(best_match=False), find_element_by_text (default best_match=False) and wait_for(text=). The default find(best_match=True) still returns the enclosing element, by luck of the length heuristic. Same-origin iframes are common in rich-text editors such as TinyMCE/CKEditor classic and in srcdoc widgets, so realism is medium.

## Lens: fixsafety (verdict confirmed, realism high, severity wrong-result)

### Summary
Confirmed on real headless Chromium (Python 3.13). util.filter_recurse (util.py, filter_recurse ~L173) only walks .children and .shadow_roots[0]. DOM.getDocument(pierce=True) puts a same-origin iframe's document only under IFRAME.content_document, so every lookup by node_id or backend_node_id misses iframe nodes. Affected: Element.update, Element.parent, Element.remove_from_dom, Tab.query_selector(_all) result trees, and the main loop of Tab.find_elements_by_text. The minimal fix descends into content_document for raw cdp nodes inside filter_recurse only. Element.text opts out so it keeps textContent semantics. filter_recurse_all is left alone because Element.children already descends into iframes. On its own, the fix still leaves duplicate text matches; the R36 dedup removes them.

### Refinements
The fix belongs in filter_recurse only. Changing filter_recurse_all as well would change text_all and cloudflare's shadow-host scan, and would duplicate nested-iframe hits (Element.children already enters content_document). Element.text must opt out: without the opt-out, <div><iframe srcdoc='<p>inside</p>'></iframe>tail</div>.text changes from 'tail' to 'inside' (verified on Chromium). R28 must ship with the R36 dedup, or A5.9 becomes [span, span] and nested iframes give [B, B] (verified). A5.5(b) belongs with R29/A8.8.
