## Lens: reproduce (verdict confirmed, realism medium, severity wrong-result)

### Summary
All three ContraDict members reproduced browser-free. (1) update(), update(**kw), setdefault() and |= store plain dicts, so nested attribute access raises AttributeError; | also returns a plain dict. (2) After copy.copy() or a pickle round trip, deleted or popped keys are still returned as attributes, and vars(copy) is not the copy. deepcopy and the original behave correctly. (3) Assigning an existing ContraDict or list stores a converted copy, so later changes to the original are not seen, and copy.copy deep-copies nested mappings.

### Refinements
A11.5 also covers update(**kwargs) and the | operator (which returns a plain dict, not a ContraDict). A11.6: copy and pickle rebuild through __reduce_ex__ without __init__, so instance __dict__ becomes a separate real dict and goes stale; __getattribute__ then falls back to object.__getattribute__ and finds it. Values replaced through __setitem__ read correctly (dict lookup comes first); only deleted keys go stale. A11.8 is partly a design choice: wrapping needs conversion, but an existing ContraDict could be stored as is.

## Lens: refute (verdict confirmed, realism low, severity wrong-result)

### Summary
All three ContraDict behaviours reproduce offline. update, setdefault and |= store raw dicts, so nested attribute access fails. copy.copy and pickle copies keep returning deleted keys as attributes. Assigning a ContraDict or list stores a converted copy. Realism is low: zendriver itself only puts flat string values into ContraDicts (Element.attrs via _make_attrs, Browser.info from /json/version) and never copies or pickles them. A11.8 is partly by design, since the docstring says dict assignments are converted.

### Refinements
Only user code that puts nested dicts into a ContraDict via update, setdefault or |=, or that copies or pickles a ContraDict and then deletes keys, can hit these. Library-internal ContraDicts hold flat strings, and attribute access on string values is unaffected by A11.5 and A11.8. A11.6 needs a copy and a later del or pop. A11.8 is consistent with the docstring's conversion promise and is closer to a design choice.

## Lens: fixsafety (verdict partially-confirmed, realism low, severity wrong-result)

### Summary
A11.5 and A11.6 are real. ContraDict.update(), setdefault() and |= bypass __setitem__ and store plain dicts. copy.copy and pickle rebuild without __init__, so they get a separate real __dict__ that keeps deleted keys readable as attributes. A11.8 also reproduces, but it is the class's documented conversion design ('dict assignments will be converted too'), not a defect. A plain dict assigned to a ContraDict is copied too. A key finding for the fix: overriding update/setdefault alone does NOT work. __getattribute__ sends warning names such as 'update' and 'setdefault' to getattr(super(), name), which is dict's method, so the overrides are bypassed when called as c.update(...).

### Refinements
The fix must also change __getattribute__'s `return getattr(super(), attribute)` to `return object.__getattribute__(self, attribute)`. Otherwise c.update and c.setdefault resolve to dict's methods. Since the instance __dict__ is self and keys are handled before that line, the result for the existing names is the same. Related but not claimed: `cd | {...}` returns a plain dict, and c.update returns the stored value if 'update' is itself a key.

### Member verdicts
- A11.5: confirmed — Python 3.13: after c.update({'a': {'b': 1}}), c.update(a={...}), c.setdefault('a', {...}) or c |= {...}, c.a.b raises AttributeError: 'dict' object has no attribute 'b'. Nothing in zendriver itself calls update/setdefault on attrs or info, so this only affects user code.
- A11.6: confirmed — copy.copy and pickle (protocols 0, 2 and 5; Python 3.11, 3.12 and 3.13): after del c['a'] or c.pop('z'), c.a or c.z still returns the old value. deepcopy does not show the stale value, but vars(c) is not c there either.
- A11.8: confirmed — The behaviour reproduces: c.child = inner, then inner.x = 1, leaves c.child == {} with c.child is inner False, and lists are copied too. But _wrap converting values is the documented design, and plain dicts are copied as well. Classed as a design choice with low realism. A partial change (return v unchanged when it is already a ContraDict) would alter copy semantics and allow self-references.
