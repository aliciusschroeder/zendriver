## Lens: fixsafety (verdict confirmed, realism medium, severity wrong-result)

### Summary
All members reproduce. circle() treats y=0 as missing (`if not y`). html_from_tree appends each child's outer HTML (which already contains its descendants) and then recurses, so a node at depth d appears d times; confirmed in real Chromium. add_extension(dir) keeps overwriting path in the rglob('manifest.*') loop and ends on the last nested match. add_extension(.crx) extracts into a mkdtemp directory that nothing ever removes; confirmed with a real browser start/stop and after the process exits. A9.11 and B16.17 are the same defect.

### Refinements
Config is documented as reusable as a template for several browsers ('config can be used/reused as a template for multiple browser instances'). So deleting the extracted crx in Browser.stop would break other or later browsers that share the Config. The safe owner is the Config itself: weakref.finalize, which runs on GC or at interpreter exit.

### Member verdicts
- A9.8: confirmed — circle(100, 0, radius=10, num=4) gives y values around 80, identical to circle(100, 100). The other part of the claim, that the circle is centred at (x-2r, y-2r), is confirmed as behaviour, but the docstring calls x and y the 'start' position. That is ambiguous, so I did not treat it as a bug or change it.
- A9.9: confirmed — Real Chromium, data:text/html,<p>hello</p>: html_from_tree gives '<html><head></head><body><p>hello</p></body></html><head></head><body><p>hello</p></body><p>hello</p>hello', while get_content gives '<html>...</html>'. Not used inside zendriver; it is a public util.

- kind: minimal-local

- diff summary: util.py: circle uses `if y is None: y = x`; html_from_tree drops the recursive call after appending each child's outer HTML. config.py: import shutil and weakref; add_extension(.crx) registers weakref.finalize(self, shutil.rmtree, tf, ignore_errors=True) right after mkdtemp; add_extension(dir) keeps path when path/'manifest.json' is a file, otherwise uses the shallowest rglob('manifest.json') match (sorted by len(parts), first one).
- risks: circle(x, 0) now really uses y=0, a change for callers who relied on the old fallback (unlikely). html_from_tree output shrinks to the de-duplicated HTML. add_extension now looks only for manifest.json (Chrome requires exactly that name), not manifest.*. The crx dir is removed when the Config is garbage-collected or at interpreter exit: if a user builds args from a Config, drops the Config and launches Chrome by hand, the dir can vanish; if a script exits while Chrome is still running, the files are deleted under it. The finalizer is registered before extraction, so a bad zip no longer leaks the dir either. No async or locking involved.
