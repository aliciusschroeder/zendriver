## Lens: reproduce (verdict confirmed, realism high, severity crash)

### Summary
All 5 members reproduced on real headless Chromium. find/find_all/wait_for/find_elements_by_text crash with AttributeError: 'Node' object has no attribute 'node' when the matching text is inside a shadow root (including the UA shadow root of <input placeholder>) in a same-origin iframe. Element.query_selector on a cross-origin iframe crashes with AttributeError on None.node_id, while query_selector_all returns []. Element-scoped query_selector(_all) silently return None/[] for an invalid selector, where the tab-level calls raise ProtocolException. Element-scoped query results have .node and .tree set to Element objects, so .parent is None at or above the queried element.

### Refinements
A6.2 confirmed mechanism: filter_recurse_all called on an Element yields Element children, but its recursion into child.shadow_roots[0] yields raw cdp.dom.Node objects, and the iframe branch of find_elements_by_text then calls .node on them. Because find() and find_all() retry until timeout, the AttributeError ends the whole call at once. Even the shadow-free part of the iframe search is lost. A5.8/B15.7: the swallowed-error branch also skips disable_dom_agent. I did not test the 'session detached'/'connection closed' variants; only the invalid-selector variant was run. A8.8 and R28/A5.5(b) are the same defect.

## Lens: refute (verdict confirmed, realism medium, severity crash)

### Summary
All 5 members reproduced on headless Chromium 141. (1) find_elements_by_text's iframe branch (tab.py:748-772) runs filter_recurse_all on an IFRAME Element. That yields Elements for normal children but raw cdp Nodes for anything under shadow_roots[0] (util.py:158-160), so `element.create(text_node.node, ...)` at tab.py:765 raises AttributeError. find/find_all/wait_for do not catch it. (2) Tab.query_selector (tab.py:622) has no content_document None guard: doc.node_id at :643 raises AttributeError for a cross-origin iframe, while query_selector_all has the guard added in #246. (3) In the except ProtocolException branches of query_selector(_all), the `_node is not None` path handles only 'could not find node' and has no else/raise, so element-scoped calls swallow other errors. (4) Element-scoped queries hand back an Element as .node and the container as .tree, so .parent is None.

### Refinements
A6.2 only happens when the matching text sits inside a shadow root (open, or a user-agent one such as <input placeholder>) inside a same-origin iframe. The AttributeError escapes on the first attempt instead of retrying until the timeout, so one such match breaks every text search for that string on the page. Main-document shadow roots are not affected. A5.3 needs a user to call query_selector on an out-of-process iframe Element instead of using get_frame()/include_frames. That is a natural thing to try with captcha and payment frames. A5.8/B15.7 only matter for element-scoped calls, and they silently turn real errors (bad selector, detached session) into 'not found'; the tab-level API and select() raise correctly. A8.8 affects any container.query_selector(...).parent (direct children of the container and anything above them), and `await elem.update()` works around it.

## Lens: fixsafety (verdict confirmed, realism high, severity crash)

### Summary
All four defects reproduce on Chromium: (1) AttributeError from find/find_all/find_elements_by_text when the matching text sits in a shadow root (including the UA shadow root of <input placeholder>) inside a same-origin iframe. filter_recurse_all over an Element returns raw cdp Nodes from shadow_roots[0], and the iframe branch calls .node on them. (2) Element.query_selector on a cross-origin iframe raises AttributeError ('NoneType' has no node_id), while query_selector_all has the guard. (3) Element-scoped query_selector(_all) swallow every ProtocolException except 'could not find node' (an invalid selector gives []/None, the tab-level call raises). (4) Element-scoped results get the container Element as tree and an Element as .node, so .parent is None at or above the scope. Minimal local fixes exist for all four. The prototype passes Chromium checks and the repo suite.

### Refinements
The tree fix must use _node.tree only when doc is _node, i.e. not for an IFRAME scope. Using the full document as the tree for IFRAME-scoped queries without the R28 descent would lose iframe.query_selector(...).parent, which works today (checked: it still works with the prototype). A8.8 and A5.5(b) are the same root cause. Re-raising is a behaviour change on Chromium: an element-scoped query on a text-node Element (for example p.children[0]) now raises ProtocolException 'Not a container node' instead of []/None (verified).
